# 语义、修订与证据交付

本轮沿既有 SQLite 知识库、本体投影、字段绑定和 Artifact 存储补齐业务定义与执行之间的追溯。

## 定义身份与来源

普通指标、规则以业务分类命名空间区分。同名定义可以分属不同空间；旧记录 ID 与未知来源状态保留。导入记录关联实际存在的来源文件，删除前可查询影响。删除来源不会静默删除人工维护或历史引用过的定义。

本体及普通定义由服务端计算内容哈希与不可变修订。相同版本文字下的不同内容和不同绑定具有不同修订引用；替换、停用、删除后仍可按旧修订读取，保留期清理显式进行。

## 分析上下文

`build_semantic_context` 固定所用定义、绑定、来源、指标契约及依赖；`validate_semantic_context` 返回 ready、needs_clarification 或 incomplete 与具体问题。只检查本次涉及的字段，缺失元数据、未映射列、未读关系、unsupported 表达式和未执行质量声明不标记为已验证。

`query_knowledge` 的可选 definition_ref 支持精确 ID/path/revision、连续分页和用户明确选择定义后的 replace_context。精确补读能推进当前上下文，不能把被长度预算省略的定义猜测为完整。

DataTools 在执行前刷新必要表字段元数据，检查源/字段漂移，并让实际 SQL 与采用的绑定一致。未知源或冲突返回明确错误，不转用同名主源。

## 证据与结果

现有 evidence claim 扩展为 v2，包含完整 SQL/参数、结果 Artifact、定义及绑定快照、执行身份、父 claim 和哈希。原生及委派工具使用同一封装；读取要求有效 grant、同会话/Workspace、内容哈希及分页上限。

分析完整结果、额外模型元数据和输入指纹使用既有 tool-result Artifact 留存。可查询派生表被新分析替换后，历史 Artifact 仍可读取。哈希与已存结果支持复核；未留存输入时不承诺复算远程历史数据。

## 验证

语义域的 88 项聚焦测试覆盖旧库迁移/回滚、命名空间、修订/绑定、历史 API、精确补读、源身份、字段漂移、依赖/fanout、保留期与证据隔离。主线程另有语义工具和完整结果留存集成回归。最终统一门禁结果见 [optimization-validation.md](optimization-validation.md)。
